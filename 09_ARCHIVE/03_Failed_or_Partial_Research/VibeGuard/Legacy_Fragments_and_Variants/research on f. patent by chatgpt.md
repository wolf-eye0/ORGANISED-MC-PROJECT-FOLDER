## Prior-Art Patent Search  
We searched patent databases (USPTO/EPO/Google Patents, etc.) for “machine vibration sensor,” “wireless vibration sensor,” and related terms, focusing on passive single-point sensors with onboard processing. Relevant patents and applications were identified, as summarized below (dates and jurisdictions omitted for brevity):

- **US9453854B2 / EP2913643A2 (KCF Technologies)** – Claims a self-contained *vibration sensor* module: *“a sensor comprising: a base… configured to be secured to a host structure; an accelerometer… centered over said base; a circuit arrangement… to receive signals from the accelerometer; and a battery… centered over said accelerometer and said base.”*.  Optional claims add a wireless transceiver and antenna on the circuit board. This device is a single-node wireless vibration sensor designed for machine health monitoring (center-of-mass alignment to improve measurement accuracy).  
- **US9578398B2 (Campbell Sci. / ABB)** – Claims a *wireless vibration sensor* with multiple processors and power management. Claim 1 recites: *“at least one vibration sensor… a processor processing vibration data… and a wireless radio transmitter transmitting said vibration data,”* plus *“an independent and self-contained power source”* and a power-storage capacitor to boost transmitter power. The enclosure is metal, and the processor sleeps until polled. Essentially, an autonomous wireless accelerometer node with battery and capacitor-based power boost.  
- **JP7832729B1 (Shinkawa Sensor Tech.)** – A Japanese patent (published 2026) for a *wireless vibration sensor* emphasizing data reduction. The abstract (translated) describes: the accelerometer’s raw waveform is *“divided into waveform data for each specific frequency band,”* and a subset of these band-specific data is selected and transmitted. A frequency-band-switching unit allows a low-power MCU to process only one band at a time. In short, it claims on-board signal processing (FFT/band filtering) to minimize wireless data volume.  
- **US11429900B2 (Tractian Limited)** – A method/system patent (granted Aug 2022) for fault detection. Its abstract describes: *“A sensor device… detects vibrations… and transmits the vibration data to a remote processing device. The vibration data may be compressed prior to transmission… [A] machine learning model… identifies a motion pattern associated with an error condition… An alert… is transmitted…”. Thus, this claim covers a vibration sensor sending (optionally compressed) data to a remote ML analyzer that predicts failures. Tractian’s published materials confirm the same: the sensor captures vibration data at high rate (e.g. 32 kHz) and uses on-device compression to send data for cloud ML analysis.  
- **US5602757A (1986/1997, expired)** – An older *vibration monitoring system* for predictive maintenance. It uses an on-machine sensor (accelerometer) feeding a microcontroller that compares FFT spectra to stored “benchmark” signatures. Notably, the controller can *“communicate…predetermined operational commands to the monitored machine”* based on analysis (i.e. it actively commands the machine). This is *active* rather than purely passive monitoring, and the patent is expired. (It confirms the general idea of on-machine analysis, but includes machine-control, so it lies outside our passive concept.)  
- **US12496907B2 (Mitsubishi Electric)** – A *failure-sign determination device* that acquires vibration data from multiple sensors, runs FFTs, and only transmits data when an anomaly is detected. This is multi-sensor and onboard processing to reduce data, but goes beyond a single-node (uses many sensors) and is tailored to vehicles (onboard, multi-sensor). It shows the approach of edge-FFT and event-triggered reporting, but is not a single point sensor node.  

## Patent Analysis and Risk Assessment  
From the above, the most directly relevant patents are those for **single-point vibration sensors with local processing/transmission**. Key risks:

- **KCF Technologies (US9453854B2/EP2913643A2)** – The claims cover exactly a one-piece vibration sensor with an accelerometer, electronics and battery housed together. If VibeGuard’s design uses a similar chassis or electrical layout (e.g. a centered piezo accelerometer, PCB and battery as claimed), it could infringe. *Risk:* High for mechanical/design overlap.  To mitigate, VibeGuard could modify the sensor geometry (e.g. not “centered” mass as claimed) or use a different mounting approach. The presence/absence of a wireless transceiver in claim 1 is not required, but claims 4–5 explicitly add a wireless transmitter, which overlaps if VibeGuard transmits data. If our device is purely wired (unlikely), that claim might be avoided; if wireless, it likely falls within.  
- **US9578398B2** – This claims a similar wireless vibration node with power conditioning (capacitor) and multiple processors. If VibeGuard includes a sleep-mode microcontroller and a capacitor-boosted transmitter, that could infringe Claim 1. However, if VibeGuard simply uses a standard battery and MCU without the specific power-storage scheme or rugged enclosure, it may avoid the narrow features. *Risk:* Moderate. We should ensure our power design and casing differ (e.g. use a different topology or IP rating) to avoid claims about metal housing as heat sink or ATEX safety resistors.  
- **JP7832729B1** – This patent claims the specific on-board processing method: segmenting vibration into frequency-band data and selecting only parts to transmit. If VibeGuard’s edge algorithm does **band-limited sampling or selective-frequency transmission**, it risks infringement. If instead VibeGuard does simpler processing (e.g. time-domain thresholding, envelope detection, or only summary stats), it likely steers clear. *Risk:* Low-to-Moderate. VibeGuard should avoid claimed features like band-by-band FFT and “partial waveform extraction” as described.  
- **US11429900B2 (Tractian)** – The claims cover compressing vibration data and analyzing it with ML off-device. VibeGuard’s edge approach (doing all processing locally and *not* sending raw or reconstructed data to a cloud ML) is conceptually orthogonal. There’s no indication VibeGuard is performing ML or neural-network analysis externally. As long as the product does not implement *“compress vibration data for telemetry”* exactly as claimed, risk is low. However, if VibeGuard ever uses cloud analysis or training, it should avoid Tractian’s specific method. Currently, *Risk:* Low, since our focus is local detection.  
- **US5602757A (Mold, expired)** – All claims have expired, and the patent describes active control of the machine based on vibration, which VibeGuard does not do. No risk (and it’s expired).  
- **Mitsubishi 12496907B2** – This multi-sensor system with onboard FFT and thresholding is somewhat relevant (it also does on-edge FFT and suppresses data unless a failure sign is found). However, it requires multiple sensors and is implemented in vehicles. VibeGuard’s single-sensor concept does not infringe these claims. *Risk:* Low.  

**Summary of Risks:**  The greatest patent risk comes from KCF’s and similar patents on single-point vibration sensors (US9453854/EP2913643). Their claims cover the basic architecture (accelerometer + on-board electronics + power source). If VibeGuard’s hardware matches these elements, we could infringe. We recommend distinguishing our design (e.g. different sensor orientation, a non-standard housing) or seeking a license if features overlap. JP7832729B1 poses some risk only if we implement the same band-selective processing. Tractian’s patent focuses on cloud ML and compression methods, which our edge-centric approach avoids; thus it is not a direct threat unless our system offloads raw data. US9578398’s power-storage details should be noted, but can be designed around (e.g. using simpler power topology).
