# Chapter 06 — VibeGuard Frozen Architecture and Semester Scope

## 06.1 Controlling architecture identity

The controlling semester architecture is a **Level-1 local vibration condition monitor** comprising:

- one rigidly mounted ADXL345-class tri-axis accelerometer;
- one ESP32-class controller, with the final board variant subject to approval and purchased-board pinout verification;
- SPI sensor acquisition;
- one controlled low-voltage motor, fan or comparable rotating test article;
- repeatable normal and deliberately induced abnormal operating states;
- continuous or windowed time-domain features;
- a calibrated RMS baseline with persistence as the minimum classifier;
- triggered FFT and selected frequency-band evidence for explanation and comparison;
- optional ordinary Mahalanobis comparison only if the baseline is already working and acquisition integrity is preserved;
- local RGB indication;
- USB serial logging and exportable evidence;
- fixed mounting, orientation, sensor, sampling, firmware, rig and session records.

This identity is passive monitoring and alerting. It is not active vibration cancellation, software-security scanning, a sensor array, cloud monitoring, remaining-useful-life prediction, automatic maintenance decision-making or a field-validated source-attribution system.

**Source basis:** `03_CONCEPT_PORTFOLIO/VibeGuard/01_Final_Architecture/Phase3C_VibeGuard_Architecture_Report_Final.md` (**TIER_1**); `03_CONCEPT_PORTFOLIO/VibeGuard/01_Final_Architecture/Phase3C_VibeGuard_Memory_Final.md` (**TIER_1**); `03_CONCEPT_PORTFOLIO/VibeGuard/01_Final_Architecture/Phase3C_VibeGuard_SOP_Final.md` (**TIER_1**); Decision Register v1.2 architecture identity as validated in Part I (**TIER_1**).

## 06.2 Project purpose and bounded semester objective

The bounded semester objective is to determine whether a low-cost target-mounted accelerometer and ESP32 can **consistently distinguish a controlled normal operating state from a deliberately introduced, safe and repeatable abnormal-vibration state using local lightweight analysis without cloud processing**.

The demonstrator is intended to establish a disciplined embedded measurement chain, not a complete industrial predictive-maintenance system. It may demonstrate acquisition, calibration, local decision logic, controlled-rig repeatability, resource feasibility and a clear live output. It does not establish bearing diagnosis, universal machine thresholds, dense-machine source attribution, industrial reliability, safety certification, production self-learning or useful remaining life.

VibeGuard remains the strongest semester-build recommendation in the comparative record, but the proposed shift from OpenBraille has not been proved teacher-approved. Final concept authorization, board acceptance, Phase 4 entry and procurement remain open.

**Source basis:** `01_GOVERNANCE_AND_CONTROL/01_Project_Requirements/Teacher_Project_Requirements_and_Change_Context.md` (**TIER_1**); `01_GOVERNANCE_AND_CONTROL/02_Decision_Registers/Project_mC_Decision_Register_v1.2.md` (**TIER_1**); final architecture, memory and SOP (**TIER_1**); `04_COMPARATIVE_DECISION/03_Change_Request/Project_mC_Request_to_Change_from_OpenBraille_to_VibeGuard.docx` (**TIER_2**, request only); validated Master Manual Part I current-state reconciliation.

## 06.3 Functional architecture

The draft-safe functional flow is:

1. **Controlled mechanical state:** the guarded low-voltage rig is placed in a documented normal or induced-abnormal configuration.
2. **Physical sensing:** the rigidly mounted tri-axis sensor converts target vibration into timestamped X/Y/Z samples.
3. **Acquisition integrity:** the ESP32 reads samples over SPI using a frozen range, output-data-rate, interrupt/FIFO or timing configuration and records errors, saturation and lost/delayed blocks.
4. **Preprocessing:** the pipeline removes DC/mean offset and applies declared windowing where spectral analysis is used.
5. **Continuous low-cost features:** RMS is mandatory; peak, standard deviation/variance, crest factor and kurtosis are allowed features where implemented and documented.
6. **Minimum decision:** the system compares the approved RMS measure against a calibrated normal baseline and requires persistence before entering the abnormal state.
7. **Supporting analysis:** triggered or scheduled FFT and selected bands provide explanatory/comparative evidence. Optional ordinary Mahalanobis may compare a small normal feature space against current data.
8. **Local state/output:** the state machine reports startup/self-check, calibrating, normal, abnormal and, where implemented, fault/invalid conditions through RGB and USB.
9. **Evidence capture:** every result resolves to a reproducible sensor, mount, rig, firmware, protocol and session identity.

No step may silently add cloud dependence, a second deployed sensor, source separation, automatic diagnosis, online adaptive updating or a patent mechanism.

**Source basis:** final architecture and memory (**TIER_1**); final SOP sections on sensing, embedded processing, edge intelligence, electrical architecture, mechanical integration and validation (**TIER_1**); `03_CONCEPT_PORTFOLIO/VibeGuard/05_Roadmaps_and_Reference_Dossiers/VibeGuard_Semester_Implementation_and_Future_Research_Roadmap.pdf` (**TIER_2**, detailed implementation proposal consistent with the frozen architecture).

## 06.4 Sensor and mounting architecture

### Sensor

The frozen sensor class is **ADXL345-class**, with the final purchased module subject to authenticity and acceptance checks. The authoritative architecture selected ADXL345 for the controlled low-frequency normal/abnormal MVP and preserved a higher-bandwidth sensor only as a later upgrade possibility. The current reconciliation does not re-verify nominal bandwidth, noise, register behavior, market availability or module authenticity.

### Interface

SPI is the controlling sensor interface. The architecture report treated SPI as necessary for reliable high-rate three-axis acquisition and rejected I²C as the final full-rate path. Final SPI clock, output-data-rate and wiring values remain configuration choices to be verified on the purchased module.

### Rigid mounting

The sensor must be rigidly coupled to the target housing or a documented rigid bracket. Foam, loose breadboard placement, hand pressure and soft or magnetic coupling are not acceptable for the locked evidence run because mounting can alter amplitude and spectral response. Bolt, rigid bonded bracket or another repeatable fixed method may be used after safety and repeatability review.

### Required records

The evidence set must record:

- sensor/module identity and supplier record;
- incoming device-identity and axis-response checks;
- axis orientation and declared axis combination;
- range, output-data-rate and interface settings;
- mount ID, dimensions, fasteners or adhesive method;
- photographs before each locked session;
- whether and how the sensor was remounted;
- saturation, clipping, noise and timing observations.

A counterfeit, unstable, bandwidth-limited or saturating module must be replaced or explicitly bounded; the classifier must not be tuned around a failed sensor.

**Source basis:** final architecture sensor and mounting selections (**TIER_1**); final memory hardware and risk summary (**TIER_1**); final SOP sensing/mechanical requirements (**TIER_1**); VibeGuard implementation roadmap component-acceptance and risk controls (**TIER_2**).

## 06.5 ESP32 and acquisition pipeline

The controller is ESP32-class, with WROOM-32 and S3 variants appearing in the controlled implementation evidence. The exact permitted board is not frozen by teacher approval in the attachments. The purchased board’s pinout, regulator, USB interface and toolchain configuration must be recorded before wiring is treated as final.

The acquisition pipeline must address:

- declared accelerometer range and output-data-rate;
- achieved effective sample rate, not only configured nominal rate;
- stable timestamps or timing intervals;
- fixed block/window length and overlap;
- FIFO, interrupt, timer or other acquisition method;
- buffering and processing schedule;
- sample-read errors, saturation and timing overruns;
- dropped, delayed or corrupted block counters;
- FFT execution time and whether it interferes with acquisition;
- RAM, flash and worst-case processing use;
- a USB configuration banner and exportable raw/feature records.

The implementation roadmap proposes beginning conservatively, piloting range and rate, then freezing the lowest stable configuration that captures the discriminating evidence. These are proposals, not controlling numeric requirements. A locked result is invalid if silent sample loss, unexplained saturation or timing corruption is present.

**Source basis:** final architecture acquisition and processing pipeline (**TIER_1**); final SOP sampling, signal-quality and validation requirements (**TIER_1**); implementation roadmap acquisition-integrity, metadata and validation stages (**TIER_2**).

## 06.7 RMS baseline and persistence logic

RMS plus persistence is the controlling minimum classifier.

A safe Chapter 06 description is:

1. collect multiple approved normal calibration sessions under a stable documented configuration;
2. derive an RMS baseline and threshold using a predeclared rule;
3. freeze the rule before reviewing untouched held-out results;
4. require threshold exceedance for consecutive windows or a declared duration;
5. use hysteresis or a controlled recovery rule where implemented;
6. log decision latency, persistence delay, false alerts and missed abnormal states;
7. treat sensor/timing/mount faults separately from normal or abnormal classification.

The threshold must not be continually changed after held-out results are seen. Calibration sessions, development sessions and locked test sessions must remain separated. Randomly splitting overlapping windows from one continuous run is not valid evidence of session-level repeatability.

**Source basis:** final architecture decision recommendation (**TIER_1**); final memory minimum implementation (**TIER_1**); final SOP minimum demonstrable success and validation requirements (**TIER_1**); implementation roadmap minimum classifier, data-split and locked-run controls (**TIER_2**).

## 06.8 Triggered FFT and frequency-band evidence

Triggered FFT and selected frequency bands are supporting evidence, not automatic fault diagnosis.

The architecture permits FFT after a pre-trigger, threshold crossing or scheduled diagnostic interval. The implementation must disclose:

- actual sample rate;
- window length and window function;
- FFT length;
- frequency resolution;
- overlap or hop;
- selected bands and the physical reason for selecting them;
- execution time and resource cost;
- whether triggering misses short events;
- limits caused by sensor bandwidth, noise, mounting and alias control.

FFT may explain a repeatable spectral change and compare normal/abnormal states. It must not be described as proving a bearing defect, identifying a target source, demonstrating novelty or validating an industrial diagnostic claim.

**Source basis:** final architecture triggered pipeline (**TIER_1**); final memory two-tier processing summary (**TIER_1**); final SOP frequency-domain investigation requirement (**TIER_1**); implementation roadmap FFT and band controls (**TIER_2**); valid patent syntheses’ conventional-art assessment (**TIER_2**).

## 06.9 Optional Mahalanobis comparator

Ordinary Mahalanobis distance is an **optional normal-space comparator** over a small declared feature vector. It is not mandatory, advanced AI, a patent contribution or evidence of source attribution.

The comparator may be attempted only after the RMS/persistence baseline and acquisition-integrity stages pass. It should use a documented normal calibration set, regularized covariance where necessary and the same held-out protocol used for the baseline. It must be dropped if it delays the core build, creates unstable covariance, exceeds resource limits or fails to add useful evidence.

The architecture report’s stronger statement that Mahalanobis was the “primary target architecture” is reconciled downward by the later governing Stage 10J instruction and the implementation roadmap: RMS/persistence is the minimum; Mahalanobis remains optional and comparative.

**Source basis:** final architecture report’s multivariate recommendation (**TIER_1**, qualified by higher current reconciliation control); Stage 10J governing instruction; implementation roadmap ordinary comparator rule (**TIER_2**); valid patent syntheses showing that ordinary Mahalanobis is crowded and conventional (**TIER_2**).

## 06.10 Rig and abnormal-state design

The semester rig must be a low-voltage controlled motor, fan or comparable rotating system on a stable base. The final abnormal state must be deliberately induced, safe, repeatable, measurable and independently labelled. The evidence packet identifies a retained eccentric mass as a primary candidate and loosened mounting as a possible alternative, but the exact method remains subject to safety and repeatability approval.

Required controls include:

- a heavy or rigid base that does not walk during operation;
- a rigid motor/fan mount;
- a mechanically retained abnormality fixture;
- a physical shaft or rotating-part guard;
- emergency or immediate power disconnect;
- low-speed/current-limited bring-up;
- pre-run inspection of fasteners, guard, wiring and sensor mount;
- recorded abnormality mass, radius, position, voltage, speed/load proxy and configuration ID;
- stopped testing for movement, loosening, cracking, heating, smell, sparking, repeated resets, detached wiring or faculty instruction.

Unsafe real-machine fault induction is prohibited. The project must not depend on causing an actual industrial failure. An unguarded rotating mass must not be improvised for presentation impact.

**Source basis:** final architecture test-scenario and mechanical selections (**TIER_1**); final SOP normal/abnormal requirements (**TIER_1**); implementation roadmap rig and safety design (**TIER_2**).

## 06.11 RGB indication and USB logging

The minimum local interface provides clear state indication and auditable evidence.

A reconciled state model is:

- startup/self-check — configuration and sensor checks;
- calibrating — blue indication and USB status;
- normal — green;
- abnormal — red after persistence;
- fault/invalid — separately logged and, if implemented, visibly distinguishable from normal/abnormal.

USB logging should include the configuration identity, timestamps, X/Y/Z or declared processed values, feature values, state transitions, threshold/persistence version, read errors, saturation, dropped blocks and session metadata. A final review should include exportable logs or CSV, not only LED behavior.

A future Unknown/Interfered state belongs to post-semester attribution research and must not silently replace the frozen Level-1 three-state demonstration. Any later UI change requires explicit approval.

**Source basis:** final architecture indication requirement (**TIER_1**); implementation roadmap state machine, metadata and demonstration plan (**TIER_2**); valid syntheses’ separation of Level 1 from later abstention (**TIER_2**).

## 06.13 Minimum demonstrable success

Minimum demonstrable success requires all of the following:

1. the selected ESP32 and accelerometer pass incoming acceptance and self-check;
2. the sensor is rigidly mounted with recorded orientation and configuration;
3. stable timestamped acquisition is demonstrated with integrity counters;
4. safe repeatable normal and induced-abnormal rig states are independently labelled;

7. RGB indicates the state clearly;

9. at least one untouched session/day/remount is evaluated without threshold changes;

## 06.15 Quantitative success and failure criteria

No controlling source has approved final Level-1 numeric thresholds. The roadmap’s figures are **proposed preregistration targets only** and become binding only after teacher/owner approval. They include at least three days of independently started normal/abnormal sessions, one held-out day/remount, proposed sensitivity and specificity of at least 90%, no more than one alert in a ten-minute locked stable-normal run, proposed decision latency within two seconds, full Level-1 decision coverage except logged invalid faults and zero lost analysis blocks in the locked run.

The reconciliation adopts the **categories**, not the numbers, as mandatory:

- independent session/day/remount evidence;
- sensitivity and missed-detection reporting;
- specificity and false-alert reporting;
- confusion matrix and class counts;
- decision latency and persistence delay;
- acquisition loss, saturation and timing integrity;
- reproducibility by a second operator;
- resource use and known limits.

Before the locked run, the authorized project owner must approve exact thresholds, session counts, allowed exclusions, hold-out structure, latency limit and failure/kill rules. Failure to meet an approved target must be reported, not repaired through post-hoc threshold changes.

**Source basis:** implementation roadmap proposed Level-1 acceptance targets (**TIER_2**, explicitly unapproved); Part I open-decision register and VibeGuard threshold status; Stage 10J requirement to preserve unresolved criteria.

## 07.6 PIRG hypothesis

The controlling sources do not define an expansion of the acronym **PIRG**. No expansion is invented here.

### Broad synthesis-level hypothesis

The valid syntheses describe a broad label-aware, contamination-protected, confidence-gated single-node target-attribution loop. In that broad version, independently known target/interferer states support target-conditioned fingerprints and an interference representation; the system separately scores target departure and source ambiguity; it can abstain rather than force a target-fault label; update admission is guarded so faults or changed interference are not learned as normal; and remount validity either enables a validated transfer or forces recalibration.

### Narrowed pre-build candidate

The later pre-build simulation concludes that the broad mechanism should be **redesigned before testing** and preserves a narrower first candidate:

1. During independently labelled commissioning, form one contrast subspace from paired measurements where the **target changes while the interferer is held fixed**.
2. Form a second contrast subspace from paired measurements where the **interferer changes while the target remains normal**.
3. At runtime, use one permanent target-mounted sensor to produce a deviation vector.
4. Compare the deviation against the two contrast structures through projection residuals and an anomaly gate.
5. Output Target-Abnormal only when the event is anomalous and fits the target-change structure materially better than the interference-change structure.
6. Output Unknown for ambiguous, out-of-support or mount-invalid observations.
7. Keep the semester RMS/FFT/Mahalanobis methods as mandatory conventional baselines.
8. Defer quarantined shadow-baseline promotion/rollback until the attribution core independently passes.
9. Treat remount transfer as unproved; the default first rule is model invalidation and recommissioning.

### Relationship to the ordinary MVP

The PIRG candidate uses the same target-mounted sensor and local embedded measurement platform but is **not part of the Level-1 semester build**. It requires a separately controlled dual-machine/factorial research rig, temporary synchronized references for independent ground truth, blocked held-out sessions/remounts, conventional baselines and later field-like evidence.

### Required evidence and baselines

Mandatory comparisons include RMS plus persistence, ordinary FFT/bands, ordinary Mahalanobis, static baseline/spectral comparison, naive adaptation where relevant and a strong one-sensor frequency-domain classifier on the same blocked splits. Critical ablations must remove the target/interference contrast, ambiguity/Unknown gate, mount-validity rule and any later update protection separately.

### Failure conditions

The hypothesis fails if target and interference contrasts are collinear or unstable; projection geometry does not generalize to held-out interference/remount blocks; apparent gain depends on leakage, nearly universal abstention or a permanent reference sensor; the sensor does not observe the useful band; edge execution drops data or violates resource limits; or independently labelable field-like conditions cannot be obtained.

### What remains unproved

No source proves observability, novelty, non-obvious synergy, enabling parameters, useful Unknown coverage, remount transfer, contamination-safe updating, field generalization, current legal status, claim value or FTO.

**Source basis:** broad mechanisms in both valid syntheses (**TIER_2**); narrowed paired-intervention candidate and “redesign before testing” conclusion in `03_CONCEPT_PORTFOLIO/VibeGuard/04_PreBuild_Simulation/VibeGuard_PreBuild_Future_Patent_Case_Simulation.md` (**TIER_2, conditional simulation**).

## 07.7 Target-source attribution and non-identifiability

One target-mounted accelerometer measures a mixture shaped by target vibration, neighbouring sources, structural coupling, speed/load, mounting and sensor limits. A clean isolated-rig result does not show that target-specific information survives realistic interference.

Target attribution therefore requires independently labelable ground truth. Temporary reference sensors, tachometers, command logs or other instruments may be used as experiment references, but they do not silently become permanent product hardware. A valid research design must vary target and interferer states independently and measure **wrong-source attribution**, not only binary anomaly accuracy.

The hypothesis must remain falsifiable. If target and interference effects occupy the same or unstable subspace, if remounting destroys the contrast or if the single sensor lacks sufficient observability, the correct conclusion is non-identifiability under the tested conditions—not a silent shift to a sensor array, cloud service or different concept.

**Source basis:** both valid syntheses’ Level-1/Level-2 distinction (**TIER_2**); pre-build simulation uncertainty and paired-intervention design (**TIER_2/conditional**); Stage 10J non-identifiability rule.

## 07.8 Ambiguity, abstention and validity-state hypotheses

A later attribution system may use an explicit **Unknown** or **Interfered** state when source attribution is unsupported. This state is a research hypothesis, not a frozen semester output.

A useful abstention mechanism must:

- use separately calibrated ambiguity or contrast evidence;
- reduce wrong target-fault labels at a declared, useful decision coverage;
- report risk/coverage or error/coverage behavior;
- avoid hiding failures through nearly universal abstention;
- block Target-Abnormal when the observation is out of support or mount-invalid;
- remain distinct from ordinary sensor/read/timing fault handling.

The later user interface for Unknown is not approved. It must not silently map to the Level-1 red or green state.

**Source basis:** both valid syntheses’ confidence-gated/three-way decision hypotheses (**TIER_2**); pre-build simulation narrowed Unknown rule (**TIER_2/conditional**).

## 07.9 Protected update and contamination-control hypotheses

Protected updating addresses the risk that target faults, changed neighbours or invalid mounts enter the trusted normal model. The broad syntheses describe candidate buffering, quarantine, confidence/stability admission, rollback/freeze and separate target/interference-envelope handling.

The pre-build simulation narrows the first experiment: **do not include automatic baseline promotion in the initial PIRG core test**. Establish attribution/contrast performance first. Only then may a separate quarantined shadow-baseline experiment test:

- clean normal drift;
- neighbour/interference drift;
- seeded target faults;
- wrong or missing labels;
- power interruption;
- promotion, lockout and rollback behavior;
- auditability of every update decision.

Protected updating is not established as novel, effective or necessary. Generic guarded adaptation is known and obviousness-heavy. It survives only as a later hypothesis if it produces a measurable cooperative effect beyond static and naive adaptive baselines.

**Source basis:** valid syntheses’ contamination-guarded direction (**TIER_2**); pre-build simulation QB deferral and twelve-month roadmap (**TIER_2/conditional**).

- invalidate the previous model when validity is not established;
- require controlled recommissioning;
- study transfer mapping only as a separately preregistered hypothesis;
