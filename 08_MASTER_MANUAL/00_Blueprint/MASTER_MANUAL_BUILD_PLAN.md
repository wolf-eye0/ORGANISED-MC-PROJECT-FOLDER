# Project mC — Master Manual Build Plan

## Pass 1 — Chapter source extraction

For each chapter:

1. open every mapped Tier 1 and Tier 2 source;
2. extract controlling facts, constraints and unresolved questions;
3. record exact source paths;
4. avoid drafting conclusions at this stage.

## Pass 2 — Contradiction and status audit

Create chapter-level contradiction tables and verify:

- concept architecture identity;
- current versus historical information;
- proposal versus approval;
- semester MVP versus future research;
- validated result versus hypothetical result.

## Pass 3 — Core manual drafting

Draft in chapter order using:

1. plain-language explanation;
2. technical architecture;
3. evidence and limitations;
4. risks and unresolved tests;
5. decision implications.

## Pass 4 — Technical validation

Check:

- component and interface consistency;
- BOM and power assumptions;
- software and hardware boundaries;
- test measurability;
- patent wording;
- cross-chapter contradictions.

## Pass 5 — Fresh external verification

Before final release, verify current:

- official hardware specifications;
- Indian market prices;
- relevant patent and technical developments;
- institutional or course requirements that may have changed.

External research must be clearly separated from frozen project-source content.

## Pass 6 — Teacher-readable edit

Produce a concise executive layer while retaining detailed technical sections
and appendices for team members and future reviewers.

## Pass 7 — Publication

Create and validate:

- DOCX;
- PDF;
- table of contents;
- page numbers;
- headers and footers;
- source register;
- change log;
- release checksum manifest.
