## 2. Technical Grounding Synthesis (Physical Testbed, Firmware & Telemetry Architecture)

### 2.1 Microcontroller Processing Architecture & Hardware Determinism
The as-built VibeGuard system executes on an Espressif Systems ESP32-D0WD-V3 SoC (7Semi DEVKIT-E module) featuring dual Xtensa LX6 32-bit cores running at 240 MHz (600 MIPS). Core 1 is dedicated to bare-metal sensor acquisition, digital filtering, and condition state classification, while Core 0 handles underlying system housekeeping. To guarantee deterministic real-time performance and prevent heap fragmentation, dynamic memory allocation (`malloc`, `calloc`, `new`) is strictly prohibited in the real-time execution loop.

| PIN_CS        | GPIO 21        | Output (MCU)  | CS (Pin 7)    | Chip Select  |

#### Engineering Rationale for CS Remapping (GPIO 21):
Standard ESP32 VSPI default maps Chip Select to `GPIO 5`. However, `GPIO 5` is a hardware strapping pin controlling SDIO slave timing and flash boot voltage. An external sensor holding `GPIO 5` LOW or HIGH during power-on causes bootloader lockup. In `VibeGuard_Autotune_Synchronized.ino` (lines 28–31), Chip Select is deliberately remapped to **`GPIO 21`** (a clean, non-strapping general-purpose bidirectional IO), ensuring cold-boot reliability.

#### SPI Bus Timing & Mode Configuration:
- **Bus Speed:** 1.0 MHz (`SPI_SPEED 1000000`). Selected to guarantee sharp edge transitions ($t_r, t_f < 15\,\text{ns}$) and prevent ringing on 150 mm breadboard prototype wiring.
- **SPI Mode 2 Selection ($\text{CPOL}=1, \text{CPHA}=0$):** SCK idles HIGH; data is output by the ADXL345 on the falling edge and latched by the ESP32 on the rising edge, perfectly satisfying ADXL345 register setup requirements.
- **Initialization Sequence (`VibeGuard_Autotune_Synchronized.ino`, lines 536–549):**
  1. Handshake verification: Reads register `0x00` (`DEVID`); asserts silicon ID equals `0xE5`.
  2. Standby transition: Writes `0x00` to `POWER_CTL` (`0x2D`) to inhibit charge-pump latch errors.
  3. Bandwidth configuration: Writes `0x0D` to `BW_RATE` (`0x2C`), setting Output Data Rate to 800 Hz (400 Hz analog Nyquist corner).
  4. Format configuration: Writes `0x0B` to `DATA_FORMAT` (`0x31`), enabling Full Resolution mode ($3.9\,\text{mg/LSB}$) across $\pm 16\text{ g}$.
  5. Active measurement: Sets Bit 3 (`Measure`, `0x08`) in `POWER_CTL`.
- **Multi-Byte Burst Readout (`readAccelBurst`, lines 518–534):** Transfers address byte `0xF2` (`ADXL345_REG_DATAX0 | 0x80 | 0x40`), commanding an auto-incrementing sequential readout across all 6 data registers ($X_0, X_1, Y_0, Y_1, Z_0, Z_1$) in a single $75\,\mu\text{s}$ transaction.
- **Microsecond Busy-Wait Timing Engine (lines 557–573):** Operating system tick delays suffer from 1.0 ms quantization jitter. VibeGuard enforces microsecond counter busy-wait pacing (`SAMPLE_PERIOD_US = 1250UL`, corresponding to $1 / 800\,\text{Hz}$), calling `yield()` to feed the FreeRTOS Task Watchdog Timer while holding timing jitter below $2\,\mu\text{s}$.

### 2.3 Mathematical Implementation of Quadrature Tare Floor Removal
In real-world industrial installations, accelerometers measure ambient structural noise (seismic tremors, acoustic reverberation, adjacent machine vibration transmitted through foundations) in addition to internal machine unbalance. 

#### Failure of Linear Subtraction:
Linear amplitude subtraction ($V_{\text{err}} = V_{\text{raw}} - V_{\text{floor}}$) is mathematically and physically invalid for stochastic AC signals. It assumes perfect phase coherence and $180^\circ$ phase opposition, which never occurs in uncorrelated vibration processes. Applying linear subtraction causes severe under-reporting of defect severity.

#### Root-Difference-of-Squares (RDS) Derivation:
Representing total measured acceleration as machine signal $s(t)$ plus uncorrelated ambient noise $n(t)$:
$$\text{RMS}_{\text{raw}}^2 = \mathbb{E}\left[(s(t) + n(t))^2\right] = \mathbb{E}[s^2(t)] + \mathbb{E}[n^2(t)] + 2\,\mathbb{E}[s(t)\,n(t)]$$
Because $s(t)$ and $n(t)$ originate from distinct physical processes, cross-correlation $\mathbb{E}[s(t)\,n(t)] = 0$. Therefore, energies add orthogonally in quadrature:
$$V_{\text{raw}}^2 = V_{\text{net}}^2 + V_{\text{floor}}^2 \implies V_{\text{net}} = \sqrt{\max\left(0,\, V_{\text{raw}}^2 - V_{\text{floor}}^2\right)}$$

#### As-Built C/C++ Firmware (`VibeGuard_Autotune_Synchronized.ino`, lines 630–637):
```cpp
if (out.valid && g_tare_floor_g > 0.0005f) {
  float raw_sq = out.vector_rms * out.vector_rms;
  float tare_sq = g_tare_floor_g * g_tare_floor_g;
  float net_sq = raw_sq - tare_sq;
  out.vector_rms = (net_sq > 0.0f) ? sqrtf(net_sq) : 0.0f;
  out.condition_vrms = out.vector_rms;
}
```
The condition `g_tare_floor_g > 0.0005f` bypasses square root calculations when tare is unconfigured, and the clamp `net_sq > 0.0f` prevents NaN generation.

### 2.6 Two-Layer Debounce Hysteresis State Machine
To eliminate false alarms caused by transient non-periodic mechanical shocks (e.g., accidental tool drops) and prevent mechanical relay chatter, VibeGuard implements an asymmetric two-tier defense:

```
[Live Window Metrics]
         │
         ▼
[Layer 1: Amplitude Corridors]
  ├── Alarm Evidence:   (V_rms >= Alarm_enter)  || (Stage_4 >= 2)
  ├── Warning Evidence: (V_rms >= Warn_enter)   || (Stage_4 == 1)
  ├── Alarm Released:   (V_rms <  Alarm_exit)   && (Stage_4 <  2)
  └── Warning Released: (V_rms <  Warn_exit)    && (Stage_4 == 0)
         │
         ▼
[Layer 2: Saturated Leaky Integrator]
  ├── Evidence Present? ──► ++Counter (Saturated at 10)
  └── Evidence Absent?  ──► --Counter (Decayed toward 0)
         │
         ▼
[State Escalation Logic]
  ├── NORMAL ──(Alarm Count >= 4)──► ALARM   [Escalation Delay: 640 ms]
  ├── NORMAL ──(Warn Count >= 4) ──► WARNING [Escalation Delay: 640 ms]
  └── ALARM  ──(Recov Count >= 6)──► NORMAL  [De-escalation Delay: 960 ms]
```

- **Escalation Latency (`warning_persist`, `alarm_persist` = 4 windows):**
  $$T_{\text{escalate}} = 4 \times 160.0\,\text{ms} = 640.0\,\text{ms}$$
  Any transient disturbance lasting $<640\,\text{ms}$ cannot trip an alarm.
- **De-escalation Latency (`recovery_persist` = 6 windows):**
  $$T_{\text{recover}} = 6 \times 160.0\,\text{ms} = 960.0\,\text{ms}$$
  The asset must run clean for nearly one full second before an alarm clears, completely preventing relay contact chatter.

### 2.8 Rotordynamic DSP & Speed-Sag Compensation Engine (`VibeGuardEngine.h`)
- **4th-Order Butterworth Cascaded Biquad Low-Pass Filter (lines 90–97):** Spur gearboxes generate acoustic tooth meshing hash ($150\text{--}350\,\text{Hz}$). Planar acceleration is filtered through two cascaded Direct-Form II Transposed biquads ($f_c = 25.0\,\text{Hz}$ at $f_s = 800\,\text{Hz}$), providing $>36\,\text{dB}$ attenuation at $150\,\text{Hz}$ while maintaining flat magnitude response at the $10\,\text{Hz}$ unbalance peak.
- **Sensorless $1\times$ Rotational Speed Tracking (lines 243–281):** Evaluates bounded-lag autocorrelation across lags $k \in [55, 105]$ ($f \in [7.62, 14.55]\,\text{Hz}$), refining the peak via 3-point parabolic interpolation:
  $$\delta k = \frac{R_{k-1} - R_{k+1}}{2(R_{k-1} - 2R_k + R_{k+1})}, \quad \hat{f}_1 = \frac{f_s}{k_{\text{best}} + \delta k}$$
  achieving sub-Hertz tracking precision ($\pm 0.05\,\text{Hz}$) without hardware tachometers.
- **Quadratic Speed-Sag Compensation Factor ($C_{\text{sag}}$, lines 283–288):** Eccentric unbalance mass adds mechanical friction, drooping shaft speed under load. Because unbalance centrifugal force scales with the square of speed ($F_c = m r (2\pi f_1)^2$), a 10% speed drop reduces unbalance force by 19%, artificially compressing vibration severity. VibeGuard dynamically normalizes condition metrics:
  $$C_{\text{sag}} = \left(\frac{f_{1,0}}{\hat{f}_1(t)}\right)^2, \quad \text{clamped to } [0.75,\, 1.45]$$
