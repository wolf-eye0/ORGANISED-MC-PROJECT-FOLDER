1. Purpose

The purpose of Phase 3B is to determine whether each shortlisted concept can realistically be implemented by the project team within the constraints of the semester project.

Unlike previous phases, Phase 3B focuses on practical engineering feasibility rather than novelty or technical possibility.

This phase identifies feasible implementation approaches, evaluates available technologies, estimates implementation complexity, and assesses whether each concept can be successfully prototyped within the available budget, timeline, and team capabilities.

The outcome of this phase is an objective engineering feasibility assessment that forms the basis for future portfolio down-selection.


The purpose of Phase 3B is not to prove that a concept can be built at any cost, but to determine whether its core engineering hypothesis can be demonstrated within the project's fixed constraints of budget, time, and team capability.

3. Objective

Evaluate each concept from the perspective of practical engineering implementation.

Determine whether the proposed engineering hypothesis can realistically be demonstrated using affordable hardware, achievable software, and reasonable development effort.

The objective is not to optimise performance, but to identify practical prototype paths suitable for an academic engineering project.

4. Scope

Phase 3B evaluates all five approved concepts:

OpenBraille
VibeGuard
TrueMoist
TrustLatch
ColdTrace

All concepts remain active during this phase.

No concepts shall be eliminated solely on subjective preference.

7. Evaluation Principles

Every concept shall be evaluated using identical engineering criteria.

The evaluation shall remain evidence-based.

Engineering optimism shall not replace objective analysis.

Unknowns shall be explicitly acknowledged.

Where multiple implementation approaches exist, they shall be compared rather than prematurely selecting one.

8. Required Evaluation Areas

For every concept, Phase 3B shall investigate:

8.1 Candidate Technologies

Identify realistic implementation technologies including:

Hardware categories
Sensors
Embedded platforms
Communication methods
Processing approaches
Storage approaches
Power options

without committing to a final architecture.

8.2 Component Availability

Determine:

Commercial availability
Educational accessibility
Typical procurement difficulty
Supplier diversity
8.3 Budget Feasibility

Estimate whether prototype implementation appears achievable within:

Preferred:

≤ ₹3000

Maximum:

≤ ₹5000

Identify major cost drivers.

8.4 Implementation Complexity

Evaluate:

Mechanical complexity
Electrical complexity
Firmware complexity
Software complexity
System integration difficulty
8.5 Team Capability Assessment

Determine whether the required skills align with the current project team.

Highlight:

Existing strengths
Required new knowledge
Expected learning curve
8.6 Development Timeline

Estimate whether implementation appears achievable within approximately two months.

Identify schedule risks.

8.7 Prototype Scope Optimization

Identify opportunities to simplify the prototype without invalidating the engineering hypothesis established during the Design Review.

8.8 Technical Risks

Identify:

High-risk components
Manufacturing risks
Algorithm risks
Integration risks
Mechanical risks
Testing risks
8.9 Risk Mitigation

For every major risk, identify practical mitigation strategies suitable for an academic prototype.

8.10 Feasibility Assessment

Classify:

Highly Feasible
Feasible
Moderately Feasible
Challenging
High Risk

Provide supporting justification.

10. Comparative Portfolio Analysis

After evaluating all concepts, produce a comparison including:

Budget confidence
Component availability
Mechanical complexity
Electrical complexity
Firmware complexity
Software complexity
Team capability alignment
Schedule confidence
Technical risk
Overall feasibility

Rank all concepts according to implementation practicality.

11. Decision Policy

Phase 3B does not eliminate concepts.

Instead, it provides objective engineering evidence that will support the Engineering Down-Selection Review after Phase 3C.

If a concept exhibits significant feasibility concerns, those concerns shall be documented rather than used as immediate grounds for elimination.

12. Out of Scope

Phase 3B shall not:

redesign concepts
optimise algorithms
produce PCB layouts
design mechanical assemblies
create firmware architecture
produce software architecture
write implementation code
perform patent analysis
estimate commercial pricing
produce manufacturing documentation

These activities belong to later phases.

13. Success Criteria

Phase 3B is considered complete when:

Every concept has been evaluated using identical engineering criteria.
Practical implementation paths have been identified.
Major engineering risks have been documented.
Budget feasibility has been assessed.
Team capability alignment has been evaluated.
Prototype scope remains consistent with the approved Engineering Design Review.
A comparative engineering feasibility portfolio has been produced.

14. Expected Outputs

Upon completion of Phase 3B, the project shall possess:

A realistic understanding of implementation feasibility for each concept.
Evidence-based estimates of cost, complexity, and schedule.
Technology options suitable for academic prototyping.
A comparative engineering feasibility portfolio.
Sufficient evidence to begin Phase 3C (System Architecture & Prototype Planning).
Objective data to support the future Engineering Down-Selection Review.
